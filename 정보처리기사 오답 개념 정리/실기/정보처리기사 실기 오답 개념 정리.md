  - 다른 객체에 자신의 필드나 메서드 은닉, 자신만의 연산으로 접근허용

- 객체지향 핵심요소
  - 객체 : 속성과 함수(메서드), 클래스의 인스턴스
  - 클래스 : 공통된 특징(속성과 연산)의 객체집합
  - 메시지 : 객체 간 상호작용

- 객체지향설계원칙(SOLID)
  - 단일책임원칙 : 모든 클래스는 하나의 책임만 가지고 책임은 캡슐화
  - 개방폐쇄원칙 : 확장에는 수정없이 변경가능하고 수정에는 닫혀있음
  - 리스코프치환원칙 : 자식클래스는 부모클래스 대체할 수 있어야 하고, 자식클래스는 확장만 수행
  - 인터페이스분리원칙 : 사용하지 않는 인터페이스는 구현하지 않고 구체적인 인터페이스를 선호
  - 의존역전원칙 : 변화없는 구체적인 클래스보다 추상클래스와 관계를 맺어야 한다

- CASE 

소프트웨어 개발 생명주기 전반에 사용되는 자동화 도구

프로젝트 일부분을 문서화하는데 다양한 기능을 제공

- 관계 다이어그램 관계 표현방법
  - 화살표 : 연관
  - 점선 화살표 : 의존
  - 마름모 화살표 : 집합
  - 비어있는 화살표 : 상속
  - 비어있는 점선화살표 : 실현

- 디자인 패턴 구조
  - 컨텍스트 : 문제가 발생하는 여러 상황 기술
  - 문제 : 패턴이 적용되어 해결될 필요가 있는 디자인 이슈 기술
  - 해결 : 설계를 구성하는 요소와 요소들 사이의 책임, 협력관계 기술

- 무결성 제약조건
  - 개체 : 기본키의 속성값은 중복, null 일수 없음
  - 참조 : 참조 릴레이션 기본키 값과 동일해야 한다
  - 도메인 : 특정 속성 값이 그 속성에 정의된 도메인에 속한 값이어야 한다.

- BCNF(보이드 코드 정규형)
  - 모든 결정자가 후보키인 정규형
  - 3NF보다 강한 정규형
  - 함수 종속에서 결정자가 후보키가 아니면 이상 현상이 발생할 수 있음

- ODBC
  - 다양한 데이터베이스를 직접 연결한 것처럼 접근하는 API, C언어 종류로 구현

- JDBC
  - Java에서 데이터베이스에 접속하고 SQL을 실행하기 위한 표준 API
  - DBMS 종류와 관계없이 Java 코드에서 DB 연동을 가능하게 함

- PL/SQL
  - 오라클 데이터베이스 시스템에 사용되는 언어로 sql을 확장하여 프로그램 기능을 추가한 것

- NoSQL
  - 빅데이터 처리를 위한 비관계형 DBMS

- RBO (Rule Based Optimizer)
  - 데이터베이스의 규칙을 기반으로 SQL 쿼리 실행 계획을 최적화하는 옵티마이저

- CBO (Cost Based Optimizer)
  - 실행계획의 비용을 고려하여 최적화를 수행하는 옵티마이저

- APM (Application Performance Management / Monitoring)
  - app의 성능, 장애, 가용성을 모니터링하고 관리하는 도구 또는 프로세스

- two-Phase Locking 프로토콜의 단계
  - 확장 : 트랜잭션이 락을 요청할 때부터 시작되어 필요한 락을 순서대로 획득하는 단계
  - 수축 : 락을 수행하지 않고 반납, 순서대로 락을 해제하는 과정

- 교착 상태 필요조건
  - 상호배제 : 자원은 하나의 프로세스나 스레드만 사용 가능
  - 점유와 대기 : 자원 점유 상태에서 다른 자원 요청하며 대기 상태
  - 비선점 : 이미 점유한 자원을 강제로 뺐을 수 없음
  - 환형대기 : 자원을 요청하는 프로세스나 스레드들이 서로 순환적으로 자원을 대기

- 트랜잭션 속성
  - 원자성 : 트랜잭션이 모두 실행이 되거나 모두 실행이 되지 않아야 한다
  - 일관성 : 실행된 결과는 DB의 일관성을 유지해야 한다
  - 독립성 : 다른 트랜잭션에 영향을 받지 않고 독립적인 실행한다
  - 지속성 : 결과는 영구적으로 DB에 저장된다

- 통합구현을 위한 연계 시스템 5가지
  - 송신시스템
  - 수신시스템

  - 연계 데이터

전문가 들의 의견을 종합하여 결론 도출

- 연계 시스템 식별 및 표준화 절차

식별 -> 데이터 매핑 -> 요소 식별 -> 요소 표준화 -> 요소 검증

- 연계 데이터 파일 형식
  - TXT, CSV, XML, JSON, EDI

- 중계 시스템 내에서 중계 모듈의 역할
  - 데이터 변환, 매핑, 라우팅, 프로토콜 변환, 보안기능

    - DTD (Document Type Definition)

  - 용도에 따른 분류 
    - SVG
    - XHTML
    - RSS
    - SOAP

  - 부분적인 업데이트
  - 동적인 UI제공
  - 보안성 떨어짐
  - 다른 작업을 동시에 수행할 수 있음
  - 브라우저 호환성

- 직접연계
  - DBLink : DB간 연결을 설정하는 오라클DB의 기능, 데이터 이동과 다른 DB의 데이터를 쿼리를 할 수 있다
  - API/openAPI
  - JDBC
  - 화면링크

- 간접연계
  - EAI : 기업 내 여러 APP을 통합하는 기술
    - ESB : EAI을 구현하는 방식 중 하나로 그 통합을 버스 구조로 구현하는 미들웨어 
    - 서비스 통합 요소 : SOAP, XML, WSDL
    - 웹서비스 보안 프로토콜 : XKMS, XACML
    - SOA 지원 기술 : BPM, ebXML
  - Socket 

- SOAP(Simple Oriented Access Protocol)
  - 인터넷에서 기능적인 요소를 제공하는 웹서비스를 구현하기 위해 사용되는 통신 프로토콜
  - XML기반 메시지 프로토콜 HTTP, SMTP, FTP 가 있음

- REST(Representational State Transfer)
  - 웹에서 데이터 구조와 처리방식을 URI로 정의, HTTP URI로 자원을 명시하고 POST, GET, PUT, DELETE 를 통해 CRUD를 적용하는 방식

- SHA-0
  - 입력과 내부상태비트 수 크기는 160으로 동일

- WSDL (Web Service Description Language)
  - 웹서비스의 기능과 메서드, 파라미터, 반환값 등의 정보를 서술하기 위한 XML기반 언어

- 공통모듈 구현 형태
  - 라이브러리
  - 프레임워크 : 추상화, 재사용성, 확장성, 역제어 특징을 가지고 있다
  - 컴포넌트 : 독립적으로 동작하는 기능

- 데이터 변환 및 접근 객체의 종류

  - DTO ( Transfer )
    - 데이터 저장, 전달을 하기 위한 객체로 별도로 정의
  - DAO ( Access )
    - DB에 접근하는 역할, 로우레벨의 데이터 접근을 수행

- jQuery : HTML 문서 조작과 이벤트 처리를 쉽게 해주는 자바스크립트 라이브러리

- selenium : 웹 애플리케이션 테스트 자동화 도구

### 화면구현

- ISO/IEC 9126
  - SW품질을 평가하기 위한 표준적이고 일반적인 국제 표준
  - 특성
    - 신뢰성
    - 사용성
    - 기능성
    - 이식성
    - 유지보수성

- UI 설계 원칙
  -  직관성 : 누구나 이해 하기 쉬워야 한다
  -  유효성 : 사용자의 목적을 정확하게 완전하게 달성
  - 학습성 : 새로운 기능을 사용자에게 쉽게 학습해서 사용할 수 있어야 한다
  - 유연성 : 다양한 요구에 대응할 수 있어야 한다

- SDLC(소프트웨어 개발 생명 주기) 산출물 4가지
  - 테스트케이스
  - 테스트계획서
  - 테스트시나리오
  - 테스트보고서

- 테스트 오라클의 종류
  - 참 오라클: 모든 입력값에 대해 기대 결과를 제공
  - 샘플링 오라클: 일부 입력값에 대해서만 기대 결과 제공
  - 휴리스틱 오라클: 경험과 추정에 따라 결과 판단
  - 일관성 검사 오라클: 변경 전후 결과의 일관성 확인

### 운영체제

- 하이퍼바이저
  - 호스트 컴퓨터에서 자수의 운영체제를 동시에 실행하기 위한 논리적 플렛폼 (가상화 머신 모니터 또는 가상화 머신 매니저)
  - 위치와 역할에 따라..
     - Type1 : 호스트 하드웨어에 직접 설치하여 구동됨, 하드웨어 위에 위치한 하이퍼바이저가 위치해 있어 운영체제의 역할와 VM들을 관리하는 역할을 모두 하이퍼바이저가 담당
     - Type 2 : 다른 App과 마찬가지로 운영체제 위에 설치되는 방식, 기존의 환경을 그대로 사용하고 설치및 구성이 편리
  - 가상화 방식에 따라..
     - 전가상화
     - 반가상화

- 정보 시스템
  - 다중프로그래밍 : 여러 개의 프로그램을 메모리에 동시에 적재하여 실행
  - 일괄처리 : 일정한 작업을 처리, 대기열에 저장하고 순차적으로 처리
  - 시분할 : 여러 사용자가 하나의 시스템을 동시에 사용할 수 있도록 각 사용자에게 일정한 시간을 할당해서 독립적으로 시스템을 사용할 수 있도록 함
  -  다중처리 : 여러 개의 CPU를 사용하여 하나의 시스템에서 여러 작업을 처리하는 방식

- 암달의 법칙
  - 프로세서를 아무리 병렬화를 시켜도 더 이상 성능이 향상되지 않는 한계가 존재한다는 법칙

- 유닉스의 구성요소
  - 커널 : 하드웨어와 프로그램 사이에서 인터페이스 역할, 하드웨어와 시스템 사이 안정성과 보안성을 유지
  - 쉘 : 사용자와 운영체제 사이에서 인터페이스 역할, 입력된 명령어를 실행

- 스레싱
  - 사용중인 프로세스 수가 증가하여 메모리가 부족해서 페이지 교체가 빈번하게 발생하는 경우

- 페이지 교체 기법
  - 최적교체 : 적재된 페이지들 중 현재 시점 이후에 가장 오랫동안 참조되지 않을 페이지 교체
  - 선입선출 : 페이지가 들어올때마다 들어온 시간을 기억하고 교체순간에 가장 먼저 들어온 페이지 교체
  - LRU : 최근에 가장 적게 쓰인 페이지 교체
  - LFU : 사용 빈도가 가장 적은 페이지 교체
  - NUR : 초기 참조와 변형 비트를 0으로 설정을 하고 참조, 변형이 되었을 때 각 1로 세트하고 교체

- 워킹셋
  - 프로세스가 일정시간 동안 자주 사용하는 페이지들의 집합

- PCB(Process Control Block)
  - 운영체제가 프로레스를 관리하는데 필요한 정보를 담고있는 자료구조로 각 프로세스마다 고유하게 할당
  - 상태전이나 CPU스케쥴링등의 이벤트가 발생할 때마다 갱신됨

- 프로세스 스케쥴링
  - 선점 
     - RR (Round Robin) : 대기시간(도착한 작업을 일정시간 할당량을 끝낸이후에 다음 작업으로 넘어가는데 다시 미완료 작업또는 작업이 시작되는데 기다리는 시간)
     - SRT (Shortest Remain time)
     - MLQ (Multilevel Queue)
     - MFQ (Multilevel Feedback Queue)
     - 선점 우선순위
  - 비선점 : CPU 를 사용하고 있는 현재 프로세스가 종료된 후 다른 프로세스를 CPU에 할당하는 방법
     - FIFO (First in First out) : 반환시간(도착시간부터 처리가 종료될 때 까지 시간)
     - SJF (Shortest Job First) : 대기 시간 = 시작시간 - 도착시간
     - HRN (Highest Response Ratio Next)
     - 비선점 우선순위

- 스풀링
  - CPU와 입력장치 간의 속도 차이를 줄이기 위해 보조기억 디스크의 일부분을 버퍼처럼 사용해서 차이를 줄이는 것

- Unix 명령어...
  - grep : 파일에서 특정 패턴을 찾고 그 패턴을 포함하는 모든 행 출력
  - ps : 현재 실행중인 프로세스를 보여주는 명령어

- 안드로이드 4가지 구성요소
  - 액티비티 : 사용자 인터페이스를 구성하는 기본단위
  - 서비스 : 백그라운드에서 무한히 실행되는 컴포넌트
  - 방송수신자 : 다른 app에서 방송하는 메시지를 받아 처리하는 요소
  - 콘텐츠 제공자 : 데이터 저장, 다른 app에서 이를 공유하기 위한 요소

### 데이터베이스

- DB의 특성
  - 실시간 접근 : SQL질의를 즉각적으로 응답해야 함
  - 계속적인 변화 : DB는 동적이므로 현제의 정확한 데이터 유지해야 함
  - 동시공유 : DB에 동시에 여러 사용자가 접근할 수 있어야 함
  - 내용에 의한 참조 : 데이터는 값에 의해 참조

- DB의 정의
  - 통합데이터 : 같은 데이터가 중복되면 안됨
  - 저장데이터 : 접근할 수 있는 매체에 저장된 데이터
  - 공통데이터 : 여러 프로그램이 공동으로 소유, 유지 가능한 데이터
  - 운영데이터 : 명확한 존재 목적과 유용성이 있는 데이터

- DB 스키마
  - 스키마 : 데이터 구조와 제약조건에 대한 명세
  - 내부스키마 : 물리적 저장구조로 어떻게 저장이 되는지 어떤 알고리즘으로 접근하는지 에 대한 스키마
  - 개념스키마 : 논리적 구조 정의, 데이터 간 관계, 제약조건, 규칙기술
  - 외부스키마 : 접근하는 응응프로그램이 볼 수 있는 논리적 구조 정의

- 커서
  - 결과집합을 한줄씩 처리하는 방법을 제공, 일반적으로 SQL쿼리를 실행하고 결과집합을 반환할 때 사용
  - 기능 데이터 조회, 데이터 조작, 데이터 이동

- DB 회복기법
  - 로그기반
     - 지연갱신 : 트랜잭션 부분완료가 될 때까지 모든 출력 연산을 지연시키고 변경을 전부 로그에 기록, Redo연산을 사용함
     - 즉각갱신 : 트랜잭션이 완료가 되면 바로 DB에 반영을 하는 기법으로 Undo연산을 사용함, 트랜잭션 장애가 발생하면 Redo연산을 사용함
   - 검사 시점 회복 기법
     - 일정 시간 간격으로 검사 시점을 만들어 메모리의 내용을 디스크에 강제로 기록하는 방법, 검사 시점 이후로 발생한 트랜잭션 에서만 Redo와 Undo를 수행
   - 그림자 페이징 기법
     - 트랜잭션이 실행될 때 테이블을 복사하여 그림자 페이지에 테이블을 생성하고 실제 트랜잭션은 원본 테이블에서 수행하는 방법, 실패할 경우 그림자 페이지로 대체

- 연쇄복귀 (Cascading Rollback, 비완료 의존성)
  - 병행수행으로 트랜잭션중 하나가 문제가 생겨 rollback하는 경우 다른 트랜잭션도 rollback을 해야 하는데 복귀를 할 수 없는 상태

- 타임스템프
  - 트랜잭션을 식별하기 위해 시스템에서 생성하는 고유번호를 부여하고 병행제어의 기준으로 사용

### 네트워크

- IPv4/IPv6 변환 방법
  -  이중스택
    - IP계층에서 두가지 모두 존재하여 통신 중 상대방에 따라 적절한 IP프로토콜을 선택할 수 있도록 함
  -  터널링
    - 송신 라우터가 IPv4로 캡슐화하여 전송하고 수신 라우터가 IPv6로 역캡슐화해서 상호간 통신가능하도록 하는 기술
  - 헤더변환
    - IPv6 와 IPv4사이 게이트웨이어세 상호간 헤더형식을 변환해주는 방법

- IPv6 특징
  -  더 많은 주소 지원 : 128비트 주소체계 사용
  - 자동구성
  - 흐름라벨링
  - 보안기능
  - 다중인터페이스
  - 유연한 확장성

- LAN 토폴로지
  - 성형 : 모든 장치가 중앙의 허브 또는 스위치에 연결되는 구조
  - 버스형 : 모든 장치가 한개의 케이블에 직렬로 연결되는 구조
  - 링형 : 모든 장치가 순환구조의 케이블로 연결되는 구조
  - 망형 : 모든 장치가 네트워크의 다른 모든 장치와 직접연결된 구조

- IEEE 802 주요 규격
  - 802.3 : 이더넷, CSMA/CD
  - 802.11 : 무선 LAN, CSMA/CA
  - 802.15 : WPAN
  - 802.16 : WMAN

- 패킷 교환 방식
  - 가상회선 
    - 데이터 전송 전에 가상의 회선을 설정, 경로는 변하지 않음
  - 데이터그램
    - 데이터 전송 전에 경로 설정을 하지 않고 패킷에 목적지 주소를 추가해 경로를 유연하게 변경할 수 있음

- 프로토콜의 기본요소
  - 구문 : 메시지의 형식 정의
  - 의미 : 의미와 목적 정의
  - 시간 : 전송의 타이밍과 순서 정의

- OSI 7 Layer

| 계층 | 이름 | 구분 | 데이터 단위 |
|---:|---:|---|---:|
| 7 | 응용 | 상위 | 데이터 |
| 6 | 표현 | 상위 | 데이터 |
| 5 | 세션 | 상위 | 데이터 |
| 4 | 전송 | 하위 | 세그먼트 | 
| 3 | 네트워크 | 하위 | 패킷 |
| 2 | 데이터링크 | 하위 | 프레임 |
| 1 | 물리 | 하위 | 비트 |

상위로 캡슐화를 해서 데이터 단위가 변함

- ICMP(Internet Control Message Protocol)
  - IP에서 오류 메시지를 보내기 위한 프로토콜로, 패킷전송 중 오류를 알리기 위해 사용
  - 주요기능 
    - 네트워크 상태 모니터링
    - 오류보고
    - 테스트 및 진단

### 소프트웨어 패키징

- DRM (Digital Right Management)
  - 저작권을 보호하고 소비자의 사용 권한을 제한하는 기술

- 클리어링 하우스
  - 저작권 라이선싱을 중개하고 라이선스 발급을 수행하는 정산소

- CMMI 5단계

초기 -> 관리 -> 정의 -> 측정 -> 최적화

- ISO 9001

  - ISO에서 개발한 품질관리 시스템의 국제표준(요구사항을 만족하고 규제준수를 위한 연속적인 개선을 관리)

- 형상관리
  - 변경사항을 체계적으로 추적하고 관리, 통제하는 프로세스
  - 절차

식별 -> 통제 -> 상태보고 -> 감사

- 베이스 라인
  - 형상관리에서 특정시점에 프로젝트의 구성요소들이 가지고 있는 공식적으로 승인된 버전

- 소프트웨어 변경제어 절차

변경사항 요청 -> 요청서 분석 -> 형상관리위원회 -> 변경구현 및 테스트 -> 시스템 설치
